# Kids: Turn-Based Messages for Parents (iOS) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** On the kid detail screen, a parent gets a third email-copy switch, `Turn-based game messages`, and a list of the kid's active turn-based games. Each row opens the existing board read-only. The board also stops treating a non-player (the parent) as player 2: message labels name both players, and a pending set-cancel request no longer asks a non-player to accept or decline.

**Architecture:** The pure logic is in Swift and unit-tested in the hosted `PenteEngineTests` target:
- `KidAccounts.swift` gains the `copyTbMessages` flag, the `settings` parameter and an `activeGames` reply parser (`KidActiveGame`).
- The new `TbViewerRole.swift` decides how the board sees the viewer: player 1, player 2 or non-player. It supplies the "me" label and decides whether a cancel request should prompt.
- `MessageAuthorLabel` takes a `myLabel` in place of the hard-coded `me`.

`KidAccountsService` gains one GET request. `KidDetailViewController` gains the switch and a games section. It pushes `BoardViewController` in the same order as the Objective-C spectator path (`MessagesViewController.m:1110-1113`: `setActiveGame:NO`, `setGame:`, `replayGame`, then disable `boardTapRecognizer`). Do not copy `PenteWebViewController.swift:166-170`: it disables the recognizer before the view is loaded (see Task 2 Step 3). `BoardViewController.m` changes only where it decides the viewer's role (the `iAmP1` line and the cancel and draw prompts) and where it writes the six `" me: "` labels.

**Tech Stack:** Swift 5 / UIKit + Objective-C, XCTest (hosted target `PenteEngineTests`, `@testable import penteLive`), CocoaPods workspace `penteLive.xcworkspace`, scheme `test1`, `xcodeproj` Ruby gem via `Scripts/add_swift_file.rb`.

## Review Focus

1. **The viewer's stored username differs in case from the server's player name.** `myUsername` is lowercased (`BoardViewController.m:2179-2180`), but the server's names may not be. A real player must never be shown as a non-player: they would lose their cancel prompt and their "me" labels. Pinned in Task 3 by `testPlayerMatchIgnoresCase`.
2. **The kid or the opponent opens the same game (regression).** Player 2 still gets `" me: "` for their own messages and still gets the cancel prompt. A player who requested the cancel themselves gets no prompt. Pinned in Task 3 by `testPlayerTwo`, `testCancelPromptOnlyForTheOtherPlayer` and `testSeatTwoIsMeForPlayerTwo` (existing), and in E2E I6.
3. **A partial or odd `activeGames` reply.** This covers one malformed game entry, missing optional fields, `lastMoveDate: 0`, an HTML login page, `success:false` with or without `error`, and a server without the action (it returns the plain GET view with no `games`, so the client gets `[]`). The other rows must still show and nothing may crash. Pinned in Task 1 by `testParseActiveGamesSkipsMalformedAndDefaultsOptionals`, `testParseActiveGamesFailures` and `testSubtitleOmitsUnknownLastMove`.
4. **Missing or empty name strings** (a player object without `name`, or an empty stored username after logout). The role helper must not crash and must treat the viewer as a non-player. Pinned in Task 3 by `testMissingNamesAreNonPlayer`. This does not cover a `null` player object: the server's `new Gson()` drops nulls, and a real `NSNull` would already fail earlier at `jsonResponse[@"player1"][@"name"]` (`BoardViewController.m:2181`), which this plan does not touch.
5. **iPad.** This covers the new section and switch in the inset-grouped table, the pushed board in both orientations, and the message popover for a non-player. The cancel sheet that used to need a popover anchor is no longer shown to a non-player. Pinned in Task 4 Step 6.
6. **An old server without `copyTbMessages`.** The TB switch row and the games section are hidden, not shown as "off" (a toggle would silently flip back on the next `run()` reload). Pinned in Task 1 by `testParseCopyTbMessages` (missing → `nil`) and in Task 2 by `testOldServerHidesTbRowAndGames`.
7. **The read-only board push.** `boardTapRecognizer` is an IUO outlet (`BoardViewController.h:88-89`) that is nil until the view loads. Disabling it before `replayGame()` traps or is lost. Pinned in Task 2 by `testMakeReadOnlyBoard` and in E2E I3.
